summary: Plan Review approval now binds to the exact plan and workflow; stale approvals no longer release execution.
category: fix
dev: Plan Review attempts capture a `reviewedInputIdentity` (plan fingerprint, resolved `WorkflowIrPin`, run/attempt identity, attempt start) before dispatch; the graph release, the terminal staleness fence, and the `approvedPlanFingerprint` anchor seam each validate it against a fresh recompute. Currentness resolves through a strict provenance classification — a failed current-workflow read is UNKNOWN and blocks, never a fail-soft default substitution. Both authority surfaces require the row's original times to be parseable and strictly ordered — completion strictly later than start — so a chronologically impossible row refuses at the graph release and at the anchor alike; the anchor additionally requires the proof's run identity to equal the current persisted lease row's genuine `leaseOwner` (re-checked at the fenced apply boundary). A refused application still persists the genuine reviewer row as honest history; only the anchor/stamp is withheld, and the refusal is named on the persistence receipt (`satisfiedApplication: "anchor-proof-refused"` at the outer proof, `"apply-check-ownership-lost"` at the fenced apply-check re-validation; absent on non-plan writes), which the fresh graph admission consumes — a non-`"applied"` receipt blocks implementation even when a later graph-side currentness read would succeed, so preserved history is never admission. The refused row also persists `planReviewApprovalRefused`, so a retained anchor cannot authorize it on a later run; a newly accepted review replaces the marker. Built-in dispatch resolves the same saved prompt overrides as the currentness/anchor checks. The log-derived recovery (`recoverPassedPlanReviewFromLatestLog`) is deleted — `[pre-merge] Workflow step completed:` log lines are audit trail only and can never grant passage. Preserve prototype-defined workflow prompt resolvers in graph dispatch and re-seed a bounded genuine Plan Review after input-identity refusal, retaining the original verdict history. Identity-refusal recovery now conditionally bypasses only the captured historical review snapshot and commits its retry count with the successor in one PostgreSQL transaction. A task-state-changed refusal retries once with fresh task/settings/workflow fences, preserving changed history, lifecycle ownership, holds and the retry budget.
