summary: A landed card whose post-merge evidence can no longer be produced is released instead of re-blocked every poll.
category: fix
dev: Two changes to the same lane. (1) The required-post-merge-gate ladder gains one resolution — `not-applicable` with reason `producer-unreachable` — admitted only by a git-probe consistency check on the card's own delivery surface: the task ref is either gone (`git show-ref --verify`) or fully contained in the merge target (`git merge-base --is-ancestor`, the landed 0/0 shape), the landing is durable, and no producer can run (no dispatchable continuation, no live step session, no fresh checkout lease). An unreadable probe answers `unknown`, which releases nothing, so the bound is git-proven and never inferred from a timer or a counter — a slow CI run is not mistaken for a vanished one. (2) A finalize refusal the lane cannot satisfy is now a durable episode on the card (`sourceMetadata.postMergeEvidenceRefusal`, key-level patch, cleared by any column change) instead of one `task:auto-merge-finalize-column-mismatch-no-action` audit row per poll; an unchanged refusal re-records at most once per 15 minutes, a changed one records immediately. RUFU-456 made a confirmed merge final on the merge fact plus whatever its workflow's required post-merge evidence demands, and this change adds one resolution to that same ladder rather than a second authority beside it: a confirmed merge whose required producer is provably gone now resolves `not-applicable` and finalizes, where the ladder previously offered only `delivery-shape`, `no-evidence-reporter` and `verdict-precedes-contract` and such a card could be released only by an operator bypass. Wherever a producer can still run the answer is unchanged — the merge fact alone still does not finalize a card — and the two cards cannot disagree about which case a card is, because both read this one ladder and the same git proof behind it. RUFU-456's shipped changeset entries are absent from this tree (consumed by a release), so this reconciliation names the card rather than a file.
