summary: A self-heal-failed review gate now parks its card visibly, and Retry discharges it without discarding the plan.
category: fix
dev: `reconcileOrphanedPendingStepResults` (`@fusion/engine` `self-healing.ts`) now owns the lifecycle it creates: when it flips an orphaned `pending` gate row to `failed` on a card that dwells in a trait-resolved `hold`-role lane and carries no status, the same `updateTask` stamps `status: "failed"` plus an explanatory `error`. It never moves the card (there is no `failed` lane), other lanes keep rewrite-only behaviour, and a card that already carries a status is left alone. That stamp is a park with a named owner: `evaluateStrandedHoldContinuation` answers `retry-owned` for `failed`/`stuck-killed`, so the stranded-hold continuation sweep no longer re-seeds the very gate whose death produced the park, and plan approval remains the other honest exit. Admission and safety for the class live in one pure core function — `classifyStrandedGateRetry({ task, ir })` with `buildStrandedGateRetryPatch` in `@fusion/core` `tasks/stranded-gate-retry.ts` — consumed by all four retry surfaces: the dashboard Retry route, `fn task retry`, extension `fn_task_retry`, and the engine's in-process chat tool. A card stranded behind a verdict-less failed required gate row is therefore discharged in place on every surface (gate row dropped so the review re-runs, approved fingerprint, step list, worktree and branch preserved, no lane move), and the destructive stage planner is skipped for that class while genuine replan shapes and explicit discard actions keep it. A deadline-derived `fn extension TaskStore boot timed out` now answers with `details.transient: "taskstore-boot-timeout"` and a retry instruction instead of a fail-closed permission denial; the boot cooldown itself is unchanged.
