# External sessions: upstream PR sequence

External sessions are observations of independently started runtimes. They are not Fusion tasks and never enter task lifecycle tables. Identity is `(Fusion project id, stable host id, provider, native session id)`; title and filesystem path are display metadata, never identity or control authority. Public contracts are provider-neutral.

1. **PR1 — core persistence + dashboard ingestion.** Core owns a versioned observation contract, project-isolated PostgreSQL migration, stable session ids, host heartbeat, and durable stream acknowledgement. Dashboard owns a domain registrar with host/project-scoped collector credentials. Focused contract, transaction/replay, auth, and migration-upgrade tests. No UI, transcript parsers, controls, runtime handles, or deployment-specific host names.
2. **PR2 — native dashboard presentation, depends on PR1.** Dashboard owns authenticated paginated list/detail/history APIs, API client, navigation, and reused presentation. Core adds bounded turn/history storage as needed. Explicit task associations or verified native ids only; native-session reconciliation cannot rely on titles/paths. Desktop/mobile, empty data, stale host, keyboard, and reconnect coverage.
3. **PR3 — isolated integrations, depends on PR1/PR2.** Provider transcript collectors and durable spools live outside the generic API. Engine/provider adapters own capability-gated launch and controls. Durable commands bind exact host/session/runtime identity, expiry, and acknowledgements; observed metadata never grants control. Historical import uses the same ingestion contract.
4. **Accounting — separate PR, depends on history contract.** Core owns provider usage normalization and reconciliation; reuse Fusion pricing with recorded provenance/effective dates. Missing telemetry stays unknown. UI adds coverage-aware cost presentation only after reconciliation tests.

Summaries, retention/search/notes, collector operational health, and historical cutover follow as bounded increments after the foundation. The 31-commit AgentPulse prototype is read-only design evidence, not a merge source. Migration 0084 is provisional until upstream landing; resolve any numbering collision by a new forward identity, never rewriting a released migration.

PR1 acceptance: one observation per native identity; retry/restart replay cannot create duplicates or regress a newer revision; acknowledgements commit with observations; gaps fail explicitly; heartbeat reflects server receipt separately from activity; collector credentials cannot access other APIs or projects. Configuration is off by default. No live Fusion or AgentPulse mutation is part of PR1.
